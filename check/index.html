10번 논문을 쓰는 앱

근거 논문: 금융권과 중앙행정기관 웹사이트의 보안 설정 비교: 보안 헤더와 구버전 TLS 차단을 중심으로 (류인수, 2026)

이 앱은 금융·공공 웹사이트 담당자가 우리 사이트의 보안 설정을 논문의 6개 항목으로 채점하고, 금융 53곳·공공 50곳과 비교해 무엇부터 고칠지 알려 줍니다.

  1. 헤더 붙여 넣고 두 가지 답하기
  2. 점수와 금융·공공 평균 비교 보기
  3. 먼저 고칠 항목 확인하고 복사하기

1우리 사이트 정보 넣기

처음이라면 예시부터 눌러 보세요. 예시는 실제 사이트가 아니라 만든 데이터입니다.

브라우저에서 F12 → Network 탭 → 새로고침 → 맨 위 문서 → Response headers를 복사해 붙여 넣습니다. 리다이렉트가 여러 번이면 논문처럼 마지막 응답만 채점합니다. 꼭 브라우저에서 복사하세요. 일부 사이트는 자동 검사 도구에 일부러 다른 헤더를 보여 줍니다.

명령어로 헤더를 받는 방법 
curl -sIL https://우리도메인/
출력 전체를 붙여 넣으면 됩니다. 단, curl 같은 자동 도구에는 사이트가 브라우저와 다른 헤더를 줄 수 있으니 결과가 이상하면 브라우저 값으로 다시 확인하세요.
① http:// 로 접속하면 https:// 로 넘어가나요?
확인하는 방법
  1. 브라우저 주소창에 http://우리도메인/ 을 http까지 직접 입력하고 엔터를 누릅니다.
  2. 주소창이 https:// 로 바뀌면(자물쇠 표시) 예, 그대로 http:// 이거나 "주의 요함"이 뜨면 아니오입니다.
개발자용: 명령어로 확인 Location: 이 https:// 로 시작하면 "예"입니다. 
curl -sI http://우리도메인/
⑥ TLS 1.0과 TLS 1.1 연결이 모두 거부되나요?
확인하는 방법
  1. 브라우저에서 SSL Labs 서버 검사(www.ssllabs.com/ssltest)를 엽니다.
  2. Hostname 칸에 도메인만 넣습니다(예: www.example.go.kr. 앞의 https:// 와 뒤의 경로는 빼기). 「Do not show the results on the boards」를 체크하고 Submit을 누릅니다.
  3. 1~2분 기다립니다. IP 주소 목록이 나오면 맨 위 것을 누릅니다.
  4. 결과를 아래로 내려 Configuration → Protocols 표를 봅니다.
TLS 1.1 No, TLS 1.0 No→ 예, 둘 다 거부
TLS 1.1이나 TLS 1.0 중 하나라도 Yes→ 아니오, 하나라도 연결됨

SSL Labs도 자동 검사이므로, 운영자가 검사를 원하지 않는 사이트에는 쓰지 마세요.

개발자용: 명령어로 확인 (윈도우에는 openssl이 기본으로 없음) 아래 두 명령이 둘 다 실패(handshake failure, no protocols available 등)하면 "예", 인증서 내용이 출력되면 연결된 것이므로 "아니오"입니다. 
openssl s_client -connect 우리도메인:443 -tls1   < /dev/null
openssl s_client -connect 우리도메인:443 -tls1_1 < /dev/null
"모름"은 0점으로 세고, 결과에 확인할 항목으로 표시합니다.

2결과와 비교

통신 보안 ① HTTPS 강제 · ⑥ 구버전 TLS 차단

0/ 2점

보안 헤더 ② HSTS · ③ CSP · ④ 클릭재킹 · ⑤ MIME

0/ 4점

논문의 핵심 결과: 금융과 공공의 차이는 통신 보안에서 났고(2점 중 1.75점 대 1.08점), 보안 헤더는 두 그룹 모두 4점 중 0.6점이 안 됐습니다(논문 표 1).

참고: 6개 항목 총점 0/6점 (논문의 판정에 쓴 값: 금융 평균 2.32점, 공공 평균 1.58점)

이 점수는 메인 페이지에 접속할 때 드러나는 보안 설정 6개(HTTPS 강제·HSTS·CSP·클릭재킹 방어·MIME 스니핑 방어·구버전 TLS 차단)가 있는지만 센 것이지, 사이트가 얼마나 안전한지가 아닙니다. 공격을 실시간으로 탐지해 막는 장치(XDR)나 웹 방화벽처럼 서버 안쪽의 방어는 점수에 나타나지 않습니다.

항목우리 사이트금융 53곳공공 50곳

금융·공공 칸은 논문 표 1의 항목별 적용률입니다(2026-11-03, 메인 페이지 3회 측정의 다수결).

3먼저 고칠 항목

빠진 항목을 측정한 사이트들이 많이 갖춘 순서대로 놓았습니다. 많은 곳이 이미 하는 일일수록 먼저 맞추기 쉽습니다.

+두 응답 비교하기

같은 사이트도 보는 쪽에 따라 다른 헤더를 줄 수 있습니다. 실제 운영자에게서 "자동 검사(스캔)에는 정보를 빼거나 다른 헤더를 보낸다"는 설명을 듣고 만든 기능입니다. 브라우저에서 복사한 헤더와 자동 도구(curl 등)로 받은 헤더처럼, 같은 사이트의 응답 두 개를 넣으면 무엇이 다른지 보여 줍니다.

항목응답 A응답 B같은가

헤더별 차이

헤더응답 A응답 B구분

날짜·캐시·요청 ID처럼 매번 바뀌는 헤더는 "매번 바뀜"으로 따로 표시하고 차이로 세지 않습니다. ①·⑥은 헤더로 알 수 없어 비교하지 않습니다.

이 앱이 쓰는 논문 결과

  • 채점 규칙: 논문 2.2절의 6개 항목을 그대로 씁니다. 항목마다 1점입니다. 성격이 다른 설정을 한데 더하지 않도록, 결과는 통신 보안 2점과 보안 헤더 4점으로 나눠 보여 줍니다.
  • 비교 기준: 표 1의 항목별 적용률을 씁니다. 이를 더해 통신 보안(①·⑥) 평균 금융 1.75점·공공 1.08점, 보안 헤더(②~⑤) 평균 금융 0.57점·공공 0.50점을 구했습니다. 총점 평균(금융 2.321점, 공공 1.580점, 금융공기업 2.125점)은 참고로 보여 줍니다.
  • 핵심 결과: 두 그룹의 차이 0.741점 가운데 0.647점이 ⑥ 구버전 TLS 차단 한 항목에서 나왔습니다(금융 89%, 공공 24%). 보안 헤더 ②~⑤는 두 그룹 모두 20% 이하였습니다.
  • 한계: 논문은 메인 페이지 한 곳에서 헤더가 있는지만 봤습니다. 점수가 높다고 설정이 올바르다는 뜻은 아니고, 로그인·거래 페이지는 따로 봐야 합니다. 또 접속할 때 드러나는 설정만 재므로 실시간 탐지·대응(XDR), 웹 방화벽처럼 서버 안쪽의 방어는 반영하지 못합니다. 점수가 낮다고 위험한 사이트라는 뜻은 아닙니다. 또 일부 사이트는 자동 검사(스캔)에 일부러 정보를 빼거나 다른 헤더를 보내므로, 논문처럼 자동 도구로 잰 값과 브라우저로 본 값이 다를 수 있습니다.

다음 연구

이 앱의 점수는 접속할 때 드러나는 설정만 봅니다. 앱으로 잰 결과를 실제 웹사이트 운영자에게 여쭤보니 "핵심 방어는 AI가 공격과 스캔을 거의 실시간으로 흘려보내는 것이고, 스캔에는 정보를 빼거나 다른 헤더를 보내는 등 여러 방식으로 대응한다"는 설명을 들었습니다. 그래서 후속 연구로 겉으로 드러나는 설정 점수와 실제 방어의 차이, 그리고 자동 측정이 실제 방문자가 받는 응답을 얼마나 정확히 보여 주는가를 계획하고 있습니다. 위의 「두 응답 비교하기」가 그 첫 도구입니다.
