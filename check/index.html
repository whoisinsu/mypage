근거 논문: 금융권과 중앙행정기관 웹사이트의 보안 설정 비교: 보안 헤더와 구버전 TLS 차단을 중심으로 (류인수, 2026)

이 앱은 금융·공공 웹사이트 담당자가 우리 사이트의 보안 설정을 논문의 6개 항목으로 채점하고, 금융 53곳·공공 50곳과 비교해 무엇부터 고칠지 알려 줍니다.

  1. 헤더 붙여 넣고 두 가지 답하기
  2. 점수와 금융·공공 평균 비교 보기
  3. 먼저 고칠 항목 확인하고 복사하기

1우리 사이트 정보 넣기

처음이라면 예시부터 눌러 보세요. 예시는 실제 사이트가 아니라 만든 데이터입니다.

브라우저에서 F12 → 네트워크 탭 → 새로고침 → 맨 위 문서 → 응답 헤더를 복사해 붙여 넣습니다. 리다이렉트가 여러 번이면 논문처럼 마지막 응답만 채점합니다.

명령어로 헤더를 받는 방법 
curl -sIL https://우리도메인/
출력 전체를 붙여 넣으면 됩니다.
① http:// 로 접속하면 https:// 로 넘어가나요?
확인하는 방법 주소창에 http://우리도메인/ 을 직접 입력해 https로 바뀌는지 보거나, 아래 명령의 Location: 이 https:// 로 시작하는지 봅니다. 
curl -sI http://우리도메인/
⑥ TLS 1.0과 TLS 1.1 연결이 모두 거부되나요?
확인하는 방법 아래 두 명령이 둘 다 실패(handshake failure, no protocols available 등)하면 "예"입니다. 인증서 내용이 출력되면 연결된 것이므로 "아니오"입니다. 공개 TLS 진단 서비스의 "Protocols" 항목으로도 확인할 수 있습니다. 
openssl s_client -connect 우리도메인:443 -tls1   < /dev/null
openssl s_client -connect 우리도메인:443 -tls1_1 < /dev/null
"모름"은 0점으로 세고, 결과에 확인할 항목으로 표시합니다.

금융·공공 평균이 낮은 이유: 대부분의 사이트가 갖춘 것은 ① HTTPS 강제(금융 87%·공공 84%)와, 금융에서는 ⑥ 구버전 TLS 차단(금융 89%·공공 24%)까지였습니다. 보안 헤더 ②~⑤는 두 그룹 모두 20% 이하였습니다(논문 표 1).

항목우리 사이트금융 53곳공공 50곳

금융·공공 칸은 논문 표 1의 항목별 적용률입니다(2026-11-03, 메인 페이지 3회 측정의 다수결).

3먼저 고칠 항목

빠진 항목을 측정한 사이트들이 많이 갖춘 순서대로 놓았습니다. 많은 곳이 이미 하는 일일수록 먼저 맞추기 쉽습니다.

  • 채점 규칙: 논문 2.2절의 6개 항목을 그대로 씁니다. 항목마다 1점, 6점 만점입니다.
  • 비교 기준: 금융 평균 2.321점, 공공 평균 1.580점, 금융공기업 평균 2.125점, 그리고 항목별 적용률(표 1)을 씁니다.
